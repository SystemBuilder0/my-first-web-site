# 03. 킬 / 스케일 — 판정 기준

> **이 문서가 시스템의 심장이다.**
> 많이 시도하는 것만으로는 아무 일도 일어나지 않는다.
> **걸러내야** 수렴한다. 걸러내지 않으면 그냥 잡동사니가 쌓일 뿐이다.

---

## 왜 임계값을 "미리" 못 박아야 하나

사후에 결과를 보면 **모든 유닛이 "조금만 더 하면 될 것 같은" 상태로 보인다.**
숫자를 보고 나서 기준을 정하면, 기준은 결과에 맞춰 휘어진다. 반드시 그렇게 된다.

특히 이 전략의 **가장 유력한 실패 모드**는 이것이다:

> 유닛을 계속 만들기만 하고 하나도 못 죽여서,
> 관리 대상만 20개로 늘어나고 어느 것도 제대로 못 굴리게 되는 상태.

분산 구조는 리스크를 낮추는 대신 **"버리는 결정"을 자주 요구한다.**
그 결정을 감정으로 하면 시스템이 아니라 그냥 취미가 된다.

**그래서 판정은 나의 의견이 아니라 표를 조회하는 행위여야 한다.**

---

## 측정하는 숫자 4개

유닛당 이것만 본다. 나머지는 노이즈다.

| 기호 | 이름 | 정의 |
|---|---|---|
| V | 조회수 | 유닛에 연결된 콘텐츠의 총 조회수 (D+14 시점) |
| E | 이메일 수집 | 랜딩에서 수집된 신규 이메일 수 |
| P | 구매 | 유료 제품 결제 완료 건수 |
| R | 매출 | P × 가격 (환불 제외) |

파생 지표 2개 — **판정은 오직 이 둘로 한다.**

```
게이트1  미끼 전환율  =  E / V      (조회수 중 몇 %가 이메일을 줬나)
게이트2  제품 전환율  =  P / E      (이메일 중 몇 %가 샀나)
```

---

## 판정 규칙 (D+14, 격주 토요일)

### 0단계 — 샘플이 충분한가

```
V < 1,000  →  판정 유예 (딱 1회, +14일)
```

- 유예는 **유닛당 최대 1회.** 두 번째 판정일에도 V < 1,000이면 → **KILL**.
- 이유: 조회수가 안 나오는 것 자체가 "이 주제는 수요가 없다"는 데이터다.
  데이터 부족이 아니라 **음성 데이터**다.

### 1단계 — 게이트1 (미끼)

```
E / V  ≥  1.0%   →  통과
E / V  <  1.0%   →  KILL (주제 폐기)
```

게이트1 실패 = **주제 자체가 사람들이 돈을 낼 만큼 아픈 문제가 아니다.**
제품을 고쳐도 소용없다. 주제를 버린다.

> 예외 1회: E/V가 0.5~1.0% 사이면 **미끼만 교체해서 1회 재시도** 가능.
> (주제는 맞는데 미끼 제목이 약했을 수 있다.) 재시도 실패 시 무조건 KILL.

### 2단계 — 게이트2 (제품)

```
P / E  ≥  2.0%   →  SCALE
P / E  <  2.0%   →  제품 교체 후 1회 재시도 (주제 유지)
재시도도 실패    →  KILL
```

게이트1은 통과했는데 게이트2가 실패 = **주제는 맞는데 상품 형태나 가격이 틀렸다.**
`04-PRODUCT-MATRIX.md`에서 다른 형태를 골라 1회만 다시 시도한다.

---

## 판정 결과별 행동

| 판정 | 즉시 할 일 |
|---|---|
| **SCALE** | 이 주제의 인접 주제로 **복제 유닛 2개** 착수. 이 유닛에는 고가 제품(2단계 사다리) 추가 검토. |
| **재시도** | 미끼 또는 제품 중 **하나만** 교체. 다음 판정일 D+14 재설정. 재시도는 유닛당 총 1회. |
| **KILL** | 랜딩·제품 페이지 내림. 로그에 **사망원인** 기록. 수집된 이메일은 메인 리스트로 병합(자산은 남긴다). |
| **유예** | 아무것도 바꾸지 않고 14일 더. 유닛당 1회. |

---

## 절대 규칙

1. **판정일에 판정한다.** 하루도 미루지 않는다. 미루는 순간 알고리즘이 멈춘다.
2. **재시도는 유닛당 총 1회.** 두 번째 재시도는 없다. (2번 고쳐서 안 되면 그건 주제 문제다)
3. **KILL은 실패가 아니라 정상 출력이다.** 진화 알고리즘에서 개체 대부분은 죽는다. 그게 설계다.
   - 예상 사망률: 유닛 10개 중 7~8개 KILL. 이게 정상이다. 이상하지 않다.
4. **살릴 이유를 찾기 시작했다면 이미 죽여야 할 유닛이다.**
5. **KILL한 유닛의 자산은 회수한다.** 이메일 리스트, 만든 PDF, 랜딩 코드는 남긴다. 죽는 건 조합이지 재료가 아니다.

## 판정일 30분 절차

```
1. (5분)  각 유닛의 V, E, P, R을 스프레드시트에서 로그로 옮긴다
2. (5분)  게이트1, 게이트2 계산 — 계산기가 판정한다, 내가 하는 게 아니다
3. (10분) 판정 결과를 로그에 기록 + 사망원인 한 문단
4. (10분) SCALE 유닛이 있으면 복제 유닛 2개의 주제를 결정
5. STATUS.md 갱신
```

**이 30분에 새 작업을 시작하지 않는다.** 판정만 한다.

## ⚠️ 임계값의 출처에 대한 정직한 고지

위 숫자(1.0%, 2.0%, V≥1,000)는 **초기 가설값이다.**
내 채널의 실측 데이터가 아니고, 검증된 업계 표준으로 확인한 것도 아니다.
"판정을 가능하게 만드는 것"이 목적이지 "정확한 값"이 목적이 아니다.

**갱신 규칙:**
- 유닛 **4개**를 완주하면, 실측 분포의 중앙값으로 임계값을 교체한다.
- 그때까지는 이 값을 그대로 쓴다. 중간에 바꾸지 않는다.
  (중간에 바꾸면 유닛 간 비교가 불가능해진다. 값의 정확성보다 **일관성**이 먼저다.)

### 실측 교체 시 사용할 규칙
```
새 게이트1 임계값 = 완주 유닛들의 (E/V) 중앙값
새 게이트2 임계값 = 완주 유닛들의 (P/E) 중앙값
```
→ 중앙값 기준이므로 자동으로 "하위 절반은 죽는다". 이게 선택압이다.
