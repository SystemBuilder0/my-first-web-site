# 06. 콘텐츠 유통 전략 — 최소 형태에서 시작해 확장한다

> 목적은 콘텐츠를 많이 만드는 게 아니다.
> **트래픽 → 이메일 → 제품**. 이 경로에 기여하지 않는 채널은 켜지 않는다.

---

## 0. 먼저 알아야 할 사실 (전략을 바꾸는 제약)

플랫폼을 고를 때 실제로 중요한 변수는 팔로워 수도 알고리즘도 아니다.
**"링크를 밖으로 내보낼 수 있는가"** 하나다. 이메일 수집이 목적이기 때문이다.

| 플랫폼 | 외부 링크 | 실질 |
|---|---|---|
| **유튜브 롱폼** | ✅ 설명란·고정댓글 | **가장 강력한 전환 채널.** 시청 시간이 길어 신뢰가 쌓인 상태에서 링크를 만난다 |
| **뉴스레터** | ✅ 제한 없음 | 이미 내 자산. 전환율 최고 |
| **쓰레드** | ⚠️ **본문 링크 시 도달 저하** | 링크는 고정 댓글로. 링크 포함 글은 10개 중 1~2개만 |
| 숏폼 (쇼츠·릴스) | ❌ 영상 내 클릭 링크 없음 | 프로필 경유만 가능. **도달 채널이지 전환 채널이 아니다** |
| X | ⚠️ 링크 도달 억제 경향 | 쓰레드와 동일 취급 |
| 링크드인 | ⚠️ 본문 링크 억제 경향 | 댓글 링크 관행. 국내 심리/자기계발 수요는 얇음 |
| 네이버 블로그 | ✅ | 2026년 들어 AI 브리핑·웹사이트 통합 노출로 **블로그 유입 자체가 하락 중** |

**여기서 나오는 결론이 이 문서 전체의 뼈대다:**

> **이메일은 사실상 유튜브 롱폼과 뉴스레터에서만 나온다.**
> 쓰레드와 숏폼은 이메일을 만드는 채널이 아니라 **유튜브로 사람을 보내는 채널**이다.

이걸 헷갈리면 숏폼을 열심히 하고 "이메일이 안 늘었다"며 잘못된 판정을 내리게 된다.

## 1. 채널별 역할과 KPI (섞지 말 것)

```
도달(Reach)  →  신뢰(Trust)  →  전환(Convert)
  숏폼·쓰레드      유튜브 롱폼        랜딩 → 이메일 → 제품
```

| 채널 | 역할 | **이 채널의 KPI** | 링크 위치 |
|---|---|---|---|
| 유튜브 롱폼 | **전환** | 이메일 수집 수 (E) | 설명란 **첫 줄** |
| 뉴스레터 | 전환 + 신뢰 | 오픈율, 구매 수 (P) | 본문 자유 |
| 쓰레드 | **팬 확보** | 팔로워 증가 수 | 고정 댓글 (본문 X) |
| 숏폼 | **도달** | 롱폼 조회수·구독자 증가 | 프로필만 |
| X·링크드인·페북 | 잉여 배포 | — (자동 배포 후에만) | 댓글 |

**절대 규칙: 도달 채널에 전환을 요구하지 않는다.**
숏폼에서 이메일이 안 나온다는 이유로 숏폼을 KILL하면 안 된다.
숏폼의 판정 기준은 **유튜브 채널 유입 증가**다.

---

## 2. 최소 폐루프 — 여기서 시작한다

극단적으로 줄이면 이것뿐이다. 채널 **1개**.

```
뉴스레터 뼈대 (주 1회 작성)
      ↓  리퍼포징
유튜브 롱폼 1편 (주 1회 발행)
      ↓  설명란 첫 줄
랜딩 → 이메일 수집
      ↓  메일 3통
제품 판매
```

**이게 닫히기 전에는 다른 채널을 하나도 켜지 않는다.**
채널을 늘리는 것은 이 루프의 **입구를 넓히는 일**이다.
루프가 닫혀 있지 않으면 입구를 넓힐수록 새는 양이 늘 뿐이다.

## 3. 핵심 레버리지 — 뉴스레터를 '에세이'가 아니라 '뼈대'로 쓴다

이 문서에서 가장 중요한 부분이다.

리퍼포징 비용은 원본의 **형식**이 결정한다.

- 아름답게 흐르는 에세이로 쓰면 → 쪼갤 수 없어서 채널마다 다시 써야 한다
- **독립적으로 성립하는 5개 블록**으로 쓰면 → 복사·붙여넣기로 끝난다

### 주간 뼈대 표준 포맷

```
[제목]   {대상}이 {상황}일 때 {구체적 결과}하는 법
[훅]     독자의 현재 상태를 그대로 묘사하는 1문장

[블록 1] 주장 1줄 + 근거·예시 2~3줄 + 실행 1줄   (150~250자)
[블록 2] 〃
[블록 3] 〃
[블록 4] 〃
[블록 5] 〃

[실행]   오늘 당장 할 것 1가지
[미끼]   관련 무료 자료 링크
```

**블록이 5개인 이유:** 주 5일 × 쓰레드 1개 = 정확히 한 주가 채워진다.
매일 뭘 쓸지 고민하는 시간이 0이 된다.

### 리퍼포징 맵 (뼈대 1개 → 한 주치 전 채널)

| 산출물 | 만드는 법 | 추가 작업 |
|---|---|---|
| 뉴스레터 | 뼈대 그대로 | 없음 (원본) |
| 유튜브 롱폼 1편 | 훅 + 블록1~5 + 실행 = 대본 | 구어체 전환, 촬영/편집 |
| 쓰레드 5개 | **블록 1개 = 포스트 1개** | 어미만 조정 |
| 숏폼 2~3개 | 롱폼에서 블록 1개 구간을 클립 | 자막 |
| 블로그 1편 | 뉴스레터 원문 + 검색형 제목 | 없음 |

**create once, distribute widely** 는 태도가 아니라 **포맷 설계**다.

## 4. 단계별 확장 로드맵

각 단계는 **앞 단계의 조건을 충족했을 때만** 켠다. 날짜가 아니라 조건이 기준이다.

### 1단계 — 뉴스레터 뼈대 (지금부터)
| | |
|---|---|
| 무엇 | 주 1회, 위 표준 포맷으로 뼈대 작성 |
| 중요 | **지금은 '발송'이 아니라 '원본 작성'이다.** 리스트가 0명이면 발송할 대상이 없다 |
| 발송 시작 조건 | 이메일 리스트 **30명** |
| 소요 | 주 3시간 |

> 이게 모든 콘텐츠의 뿌리다. 뼈대가 없으면 나머지 전 채널이 매번 백지에서 시작한다.

### 2단계 — 유튜브 롱폼 (1단계와 동시)
| | |
|---|---|
| 무엇 | 주 1회, 뼈대를 대본으로 삼아 1편 |
| 필수 | 영상 끝 20~30초 미끼 언급 + 설명란 **첫 줄** 링크 + 고정 댓글 |
| 왜 여기부터 | 이미 구독자 2.5만이 있다. **없는 트래픽을 만드는 것보다 있는 트래픽의 누수를 막는 게 먼저다** |
| 판정 지표 | E/V ≥ 1.0% (`03-KILL-SCALE.md`) |

> **1+2단계가 최소 폐루프다. 여기까지가 "최소한으로 간다면" 의 답이다.**

### 3단계 — 쓰레드 매일 (조건: 랜딩 E2E 통과)
| | |
|---|---|
| 무엇 | 뼈대의 블록 1개 = 포스트 1개, 주 5개 |
| 링크 | **본문에 넣지 않는다.** 고정 댓글에. 링크 포함 글은 10개 중 1~2개만 |
| 역할 | 이메일 수집이 아니라 **팬 확보**. 국내 활성도가 높고 텍스트→텍스트라 비용이 거의 0 |
| 소요 | 주 1시간 (뼈대에서 잘라내는 것뿐) |
| KPI | 팔로워 증가 |

### 4단계 — 쇼츠 (조건: 유튜브 롱폼 4주 연속 발행)
| | |
|---|---|
| 무엇 | 롱폼에서 블록 1개 구간 클립 → 주 2~3개 |
| 왜 쇼츠 먼저 | 같은 채널 안이라 롱폼·구독으로 되돌리는 경로가 가장 짧다 |
| 역할 | **도달.** 이메일은 기대하지 않는다 |
| KPI | 롱폼 조회수·구독자 증가 |

### 5단계 — 릴스·틱톡 동시 배포 (조건: 쇼츠 제작이 30분 이하)
같은 클립을 그대로 재업로드. **새로 만들지 않는다.** 만들어야 한다면 아직 이르다.

### 6단계 — X·링크드인·페이스북·블로그 (조건: 리퍼포징 **자동** 배포 동작)
| | |
|---|---|
| 원칙 | **수동으로는 켜지 않는다.** 수동 4채널은 순손실이다 |
| 방식 | 뼈대 → 자동 변환 → 예약 발행 (`05-AUTOMATION-ROADMAP.md` 4순위) |

### 7단계 — 두 번째 유튜브 채널 (자기개발)
조건: 유닛 001 판정 완료 + 유튜브 제작 과정이 문서화되어 재현 가능할 것.

## 5. 확장 조건 요약표

| 단계 | 채널 | 켜는 조건 | 주당 추가 시간 |
|---|---|---|---|
| 1 | 뉴스레터 뼈대 | — (지금) | 3h |
| 2 | 유튜브 롱폼 | — (지금) | 영상 제작 시간 |
| 3 | 쓰레드 | 랜딩 E2E 통과 | 1h |
| 4 | 쇼츠 | 롱폼 4주 연속 발행 | 2h |
| 5 | 릴스·틱톡 | 쇼츠 제작 30분 이하 | 0.5h |
| 6 | X·링크드인·페북·블로그 | 자동 배포 동작 | 0h (자동) |
| 7 | 유튜브 2번째 채널 | 유닛 001 판정 + 제작 문서화 | 영상 제작 시간 |

**조건을 못 채웠으면 그 채널은 안 켠다.**
조건 없이 켜면 늘어나는 건 채널 수가 아니라 **미완성 채널 수**다.

## 6. 주간 콘텐츠 루틴 (3단계까지 켜졌을 때)

| 요일 | A블록 (오전) |
|---|---|
| 월 | **뼈대 작성** (뉴스레터 원본) — 이번 주 전 채널의 원료 |
| 화 | 유튜브 롱폼 제작 |
| 수 | 유튜브 업로드 + 쓰레드 5개 일괄 예약 |
| 목 | (4주차~) 뉴스레터 발송 + 쇼츠 클립 |
| 금 | 리퍼포징 잔여 + **쓰레드 반응 집계 → 다음 주 뼈대 주제 결정** (§7 3단 승격) |
| 토 | 리뷰 / 격주 판정 |
| 일 | 오프 |

**월요일 뼈대 작성이 한 주를 결정한다.** 여기가 막히면 전 채널이 막힌다.
막혔을 때의 대응: 지난 유튜브 조회수 상위 영상의 주제를 다시 꺼내 각도만 바꾼다. 새 주제를 짜내지 않는다.

## 7. 텍스트 플랫폼의 진짜 용도 — 배출구가 아니라 **탐색 엔진**

해외 텍스트 기반 크리에이터(Dan Koe, Justin Welsh 등)를 확인한 결과,
이들이 X·링크드인·쓰레드를 쓰는 목적은 "콘텐츠를 더 많이 뿌리는 것"이 아니었다.

### 그들이 실제로 얻는 것 4가지

| 목적 | 내용 |
|---|---|
| **① 아이디어 테스트베드** | 포스트 1개 = 10분. **가장 싼 시행 단위.** 반응이 좋은 것만 뉴스레터·영상·제품으로 승격 |
| ② 사고력 증명 | 텍스트는 사고의 질이 그대로 드러난다. 사람들은 **신뢰하는 사고**에서 산다 |
| ③ 네트워크 접근 | 동료 운영자·협업·고객이 있는 곳 (특히 링크드인은 B2B·고가 상품) |
| ④ 제작비 0의 유통 | 편집·썸네일·촬영이 없다. 유일하게 매일 발행 가능한 형식 |

### 확인된 그들의 구조 (내 계획과 동일)

- **Dan Koe**: 매일 아침 30분 뉴스레터 작성 → 뉴스레터가 유튜브 대본이 되고, 소제목이 X 훅이 되고,
  문단 속 핵심이 링크드인 포스트가 된다. **"1시간의 깊은 사고 → 20개 콘텐츠"**
- **Justin Welsh (Hub & Spoke)**: 뉴스레터 1편을 6~12조각으로 잘라 X·링크드인에 배포

→ 3장의 뼈대-리퍼포징 구조는 **이들이 실제로 쓰는 것과 같다.** 이 부분은 검증된 셈이다.

### 하지만 그대로 이식하면 실패하는 지점

| | 그들 | 나 |
|---|---|---|
| 고객 | 크리에이터·전문직·창업가 | **한국 심리/자기계발 소비자** |
| 그 고객이 사는 곳 | X · 링크드인 | **쓰레드** (링크드인엔 없다) |

**이식할 것은 메커니즘이지 플랫폼이 아니다.**
→ 그들의 X·링크드인 자리에 **쓰레드**를 넣는다.
→ 링크드인·X는 나중에 **다른 오디언스(B2B·고가 컨설팅)** 를 노릴 때만 켠다.

### 그래서 추가되는 루프 — 쓰레드는 뼈대의 '출력'이자 '입력'이다

3장의 구조는 단방향이었다. 실제로는 **순환**이어야 한다.

```
        ┌──────────────────────────────────────────┐
        ↓                                          │
   쓰레드 5개 (탐색·주 5개 시행)                     │
        ↓  반응 상위 3개                            │
   다음 주 뼈대 (검증된 주제만)                       │
        ↓                                          │
   유튜브 롱폼 + 유닛/제품 (활용)  ──────────────────┘
```

**왜 이게 중요한가 — 탐색 속도가 25배 빨라진다**

| 주제 발굴 경로 | 주당 데이터 포인트 | 시행 1회 비용 |
|---|---|---|
| 유튜브 애널리틱스만 | **1개** (주 1편) | 수 시간 |
| + 쓰레드 | **5~25개** | 10분 |

`00-MASTER-PLAN.md`의 진화 알고리즘은 시행 횟수가 곧 성능이다.
**텍스트 포스트는 그 시행 단위를 가장 싸게 만드는 장치다.**

### 3단 승격 관문 — 비싼 채널엔 검증된 주제만 올린다

| 관문 | 무대 | 비용 | 통과 기준 |
|---|---|---|---|
| 1관문 | 쓰레드 포스트 | 10분 | 그 주 5개 중 **반응 상위 2개** |
| 2관문 | 다음 주 뼈대의 블록으로 승격 | 30분 | 뉴스레터/추가 포스트에서 재반응 |
| 3관문 | **유튜브 롱폼 + 유닛(제품)** | 수 시간~수십 시간 | 2관문 2회 이상 통과 |

이러면 `03-KILL-SCALE.md`의 판정 **앞단에 필터가 하나 더 생긴다.**
지금은 유닛을 다 만든 뒤에야 걸러지는데, 이 관문을 붙이면 **유닛을 만들기 전에** 걸러진다.
가장 비싼 실패(제품까지 다 만들고 KILL)의 빈도가 줄어든다.

### 반증 하나 — 종착점은 분산이 아니라 집중이다

**Justin Welsh는 약 $150짜리 코스 단 2개로 $5M 이상을 만들었다.**
제품을 많이 만든 게 아니라 **적게 만들어 오래 팔았다.**

이건 "제품을 많이 찍어낸다"는 내 전략과 충돌하는 것처럼 보이지만, 실은 **순서**다.

```
탐색 단계 : 많이 만든다  (지금)
   ↓  SCALE 판정으로 승자 확인
활용 단계 : 승자에 수렴한다  (나중)
```

**SCALE 판정의 진짜 의미는 "하나 더 늘린다"가 아니라 "여기로 모은다"이다.**
이걸 놓치면 제품 30개를 굴리는데 어느 것도 제대로 안 되는 상태로 간다.
분산은 목적지가 아니라 **승자를 찾기 위한 수단**이다.

## 8. 정직한 고지 — 확인된 것과 확인되지 않은 것

**검색으로 확인함:**
- 쓰레드는 외부 링크 포함 게시물의 도달을 낮춘다 → 링크는 고정 댓글, 비중 10~20% 권장
- 쓰레드 한국 사용 시간이 크게 증가했고 국내 활성도가 높다 (단, 메타가 국가별 사용자 수는 미공개)
- 2026년 네이버 블로그는 AI 브리핑·웹사이트 통합 노출 확대로 **유입이 하락 중** → 그래서 6단계로 내렸다

- 유튜브 설명란 링크의 실제 클릭률 → 유닛 001에서 실측된다
- X·링크드인의 현재 링크 억제 강도 → 6단계 도달 시 재확인
- 숏폼 → 롱폼 유입률 → 4단계 도달 시 실측
