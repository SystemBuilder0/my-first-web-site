# 분산 사업 시스템 (Distributed Business System)

> 이 폴더는 "읽는 문서"가 아니라 **매일 실행하는 운영체제**다.
> 아침에 앉으면 `STATUS.md` → `10-WEEK-01.md` 순으로 열고 그날 할 일만 한다.

---

## 한 문장 요약

**인간의 성장과 의미론적 방향성을 가이드하는 제품을,
콘텐츠 퍼널로 트래픽을 모아 판매하는 "유닛"을 만들고,
그 유닛을 2주에 1개씩 복제·측정·선별해서 승자만 남긴다.**

---

## 이 시스템이 푸는 문제

| 문제 | 이 시스템의 해법 |
|---|---|
| 성공은 미리 알 수 없다 | 예측을 포기하고 **시행 횟수**로 푼다 |
| 예전엔 시행 1회가 비쌌다 | AI로 시행 비용을 0에 수렴시킨다 |
| 하나에 올인하면 리스크 집중 | 유닛 단위로 쪼개서 **리스크를 분산**한다 |
| 분산하면 뭘 죽일지 애매해진다 | **사전에 못 박은 임계값**으로 기계적으로 판정한다 |
| 죽인 것에서 배움이 안 남는다 | 모든 유닛은 `logs/`에 **사망원인**까지 기록한다 |

## 절대 규칙 5개

이 5개만 지키면 나머지는 흔들려도 된다.

1. **판정일에 판정한다.** 연기 금지. "조금만 더 해보면" 금지. (`03-KILL-SCALE.md`)
2. **손으로 3번 해본 것만 자동화한다.** 안 팔리는 걸 자동화하면 안 팔리는 게 자동으로 안 팔린다.
3. **모든 콘텐츠 끝에는 미끼 링크가 있다.** 링크 없는 콘텐츠는 자산이 아니라 소모다.
4. **이메일 주소가 유일한 진짜 자산이다.** 조회수·구독자는 플랫폼이 회수할 수 있다.
5. **죽은 유닛은 사망원인을 남기고 죽인다.** 기록 없는 실패는 그냥 손실이다.
6. **도달 채널에 전환을 요구하지 않는다.** 숏폼·쓰레드는 유튜브로 보내는 역할이지 이메일을 만드는 역할이 아니다. (`06-CONTENT-DISTRIBUTION.md`)
