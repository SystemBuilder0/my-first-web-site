# 02. 유닛 플레이북 — 유닛 1개를 끝까지 관통하는 표준 절차

## 유닛이란

```
유닛 = 주제 × 무료미끼 × 랜딩 × 이메일시퀀스 × 유료제품
```

이 다섯이 다 있어야 **측정 가능한 한 덩어리**가 된다.
하나라도 빠지면 그건 유닛이 아니라 재료다. 재료는 판정할 수 없다.

- 제품만 있고 랜딩이 없다 → 팔 경로가 없다
- 랜딩만 있고 미끼가 없다 → 이메일이 안 모인다
- 미끼만 있고 제품이 없다 → 수익화 지점이 없다

**목표: 유닛 1개를 2주 안에 런칭.** (첫 유닛은 1주 목표 — 풀타임이므로)

---

## 표준 7단계

### STEP 1. 주제 확정 (30분)
- 유튜브 애널리틱스 조회수 상위 10개 영상 → 주제 태그로 묶기
- 가장 많이 반복되는 태그 1개 선택
- **판단 기준: 수요 신호 있음 + 내가 3개월 이상 다룰 수 있음**
- 산출물: `logs/UNIT-XXX-{주제}.md` 생성 (템플릿 복사)

> ❌ 하지 말 것: 주제를 상상해서 만들기. 수요는 **발명하는 게 아니라 채널에서 추출**한다.

---

### STEP 2. 무료 미끼 제작 (2시간)
관객이 **지금 당장 겪는 문제 하나**를 즉시 해결해주는 물건.

| 형태 | 제작 난이도 | 추천도 |
|---|---|---|
| 셀프체크 / 진단 PDF | 낮음 | ★★★ 1순위 |
| 1페이지 체크리스트 | 낮음 | ★★★ |
| 노션 템플릿 | 중간 | ★★ |
| 미니 가이드 (5~10p) | 중간 | ★★ |

**품질 기준:** "무료치고 좋다"가 아니라 **"이걸 왜 무료로 주지?"** 소리가 나와야 한다.
미끼의 품질이 유료 제품의 신뢰도를 결정한다. 여기만은 아끼지 않는다.

- 제목 공식: `{대상}을 위한 {구체적 결과}` — 예: "3분 만에 내 불안 유형 알아보는 셀프체크"
- 파일명에 브랜드/링크를 넣는다 (전달되며 퍼진다)

---

### STEP 3. 랜딩페이지 배포 (30분)
- `landing/_template.html` 복사 → `landing/{unit-slug}.html`
- 상단 `{{...}}` 플레이스홀더만 치환
- GitHub Pages로 배포 → URL 확보
- **이메일 폼 임베드 코드 삽입**

> **핵심 원칙: 랜딩은 영상 주제와 1:1로 일치해야 한다.**
> 불안 영상 → 불안 랜딩. 통합 랜딩("모든 심리 자료 모음") 금지. 전환율이 반토막 난다.

**랜딩이 코드라는 게 이 시스템의 핵심 레버리지다.**
템플릿 복사 + 변수 치환 = 30분. 유닛 복제 비용이 실질적으로 0이 된다.

---

### STEP 4. 이메일 시퀀스 3통 (1시간, 에이전트 위임)
| 통 | 발송 시점 | 목적 | 내용 |
|---|---|---|---|
| 1통 | 즉시 | 전달 + 신뢰 | 미끼 다운로드 링크 + "왜 이걸 만들었나" 한 문단 |
| 2통 | +2일 | 가치 | 미끼를 실제로 쓰는 법 / 사례 하나. **판매 없음** |
| 3통 | +3일 | 판매 | 유료 제품 소개. 미끼에서 못 다룬 부분을 채운다는 논리 |

3통 모두 **미리 작성해서 예약 발송으로 걸어둔다.** 수동 발송은 유닛이 늘면 즉시 무너진다.

---

### STEP 5. 유료 제품 제작 (3~4시간, 에이전트 위임)
- 미끼가 **드러낸 문제**를 해결하는 물건. (셀프체크로 "내 유형은 X" → 워크북으로 "X 유형 대처법")
- 가격: **첫 유닛은 1.0만~1.5만원.** 낮게 시작해 데이터부터 쌓는다.
- 결제 링크 생성 → 자동 전달 설정
- 후보 형태: `04-PRODUCT-MATRIX.md` 참조

> 완성도 60%에서 런칭한다. 40%는 첫 구매자 피드백으로 채운다.
> **환불 요청은 조건 없이 즉시 처리한다.** 이게 낮은 완성도로 빠르게 내는 것의 비용이자 면허다.

---

### STEP 6. 콘텐츠 발행 + 연결 (제작시간 별도)
- 유튜브 영상 제작 (주제 = STEP 1)
- 영상 마지막 20~30초에 미끼 언급: **"~를 무료로 받으세요"**
- 설명란 **첫 줄**에 랜딩 링크 (더보기 아래로 내려가면 안 됨)
- 고정 댓글에 링크 한 번 더

### STEP 6-B. 발행 전 E2E 테스트 (필수, 15분)
런칭 전 **내가 직접 고객이 되어** 전 과정을 통과한다.
- [ ] 설명란 링크 클릭 → 랜딩 열림 (모바일에서도)
- [ ] 이메일 입력 → 실제로 수집됨 (관리자 화면에서 확인)
- [ ] 1통 메일이 실제로 도착 (스팸함 포함 확인)
- [ ] 미끼 다운로드 링크가 실제로 열림
- [ ] 결제 링크 → 실제 결제 → 제품 자동 전달 (테스트 결제 1건 직접 해볼 것)

> 이 15분을 건너뛰면 2주치 트래픽을 통째로 버린다. **가장 비싼 생략이다.**

---

### STEP 7. 계측 걸기 + 판정일 예약 (10분)
- `logs/UNIT-XXX.md`에 런칭일 기록
- **판정일 = 런칭일 + 14일** 을 로그와 `STATUS.md`에 명시
- 추적할 숫자 4개 확정: 조회수 / 이메일 수집 / 구매 / 매출

---

## 유닛 체크리스트 (복사해서 쓰기)

```
[ ] 1. 주제 확정 + 로그 파일 생성
[ ] 2. 무료 미끼 완성 (PDF)
[ ] 3. 랜딩 배포 + URL 확보
[ ] 4. 이메일 3통 작성 + 예약
[ ] 5. 유료 제품 완성 + 결제 링크
[ ] 6. 콘텐츠 발행 + 링크 연결
[ ] 6-B. E2E 테스트 5개 항목 전부 통과   ← 건너뛰기 금지
[ ] 7. 판정일 D+14 예약
```

---

## 복제할 때 (SCALE 판정 이후)

승자 유닛이 나오면 **바닥부터 만들지 않는다.** 변수만 바꾼다.

| 유지 | 변경 |
|---|---|
| 랜딩 구조 | 주제 |
| 메일 시퀀스 골격 | 미끼 내용 |
| 제품 형식 | 제품 내용 |
| 가격대 | — |

복제 유닛 목표 제작 시간: **4시간 이하.**
여기까지 오면 병렬 운영의 수익이 실제로 발생하기 시작한다.

### 변이 방향 3가지
1. **인접 주제** — 불안이 되면 → 수면, 관계, 번아웃
2. **인접 형태** — 워크북이 되면 → 같은 주제로 오디오 가이드, 30일 챌린지
3. **인접 가격** — 1.5만이 팔리면 → 3만원 확장판 테스트

한 번에 하나씩만 변이시킨다. 두 개를 동시에 바꾸면 뭐가 원인인지 알 수 없다.
