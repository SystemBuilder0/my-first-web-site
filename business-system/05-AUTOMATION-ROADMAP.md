# 05. 자동화 로드맵

## 대원칙

> **손으로 3번 해본 것만 자동화한다.**

이유:
- 안 팔리는 걸 자동화하면 **안 팔리는 게 자동으로 안 팔린다.** 손실만 자동화된다.
- 3번 해보기 전엔 뭐가 진짜 병목인지 모른다. 대부분 예상과 다르다.
- 자동화는 프로세스가 고정된 뒤에만 싸다. 고정 전 자동화는 매번 다시 짜야 한다.

**예외:** 측정 자동화는 1번 만에 해도 된다. 측정은 프로세스가 아니라 인프라다.

---

## 자동화 순서 (이 순서를 지킬 것)

| 순위 | 무엇 | 왜 이 순서인가 | 착수 조건 |
|---|---|---|---|
| **1** | **측정 집계** | 판정이 안 되면 알고리즘 전체가 멈춘다. 가장 먼저. | 유닛 1 런칭 즉시 |
| **2** | **이메일 시퀀스** | 유닛이 늘면 수동 발송이 가장 먼저 무너진다 | 유닛 1 |
| **3** | **랜딩 생성** | 템플릿+치환. 유닛 복제 비용을 0으로 만든다 | 유닛 2 |
| **4** | **리퍼포징 배포** | 1소스 → N채널. SNS 확장의 전제 조건 | 유닛 3 |
| **5** | **콘텐츠 제작** | 시간은 제일 많이 아끼지만, 위가 없으면 만들어도 새어나간다 | 유닛 3 이후 |
| **6** | **수요 발굴** | 판단 영역에 가깝다. 마지막 | 유닛 5 이후 |

> **왜 제작 자동화가 5번인가:** 제작은 가장 오래 걸리는 일이라 제일 먼저 자동화하고 싶어진다.
> 하지만 측정·배포가 없으면 만든 콘텐츠가 어디로도 이어지지 않는다.
> **새는 양동이에 물을 더 빨리 붓는 것**이 된다. 구멍부터 막는다.

---

## 단계별 상세

### 1. 측정 집계 자동화
**목표:** 판정일에 숫자를 찾아다니지 않아도 되게 한다.

- 스프레드시트 1장: 행=유닛, 열=날짜별 V/E/P/R
- 자동화 대상: 유튜브 조회수, 이메일 툴 구독자 수, 결제 건수 → 매일 자동 기록
- 도구: Make (또는 n8n) + Google Sheets
- **최소 버전으로 먼저:** 자동화가 어려우면 **매일 계측 블록에 수동 3분 입력**으로 시작한다.
  측정 자체가 없는 것보다 수동 측정이 무한히 낫다.

### 2. 이메일 시퀀스 자동화
- 랜딩 폼 제출 → 태그 부여 → 3통 자동 발송 (즉시 / +2일 / +3일)
- 유닛마다 태그를 분리해야 **유닛별 전환율 측정**이 가능하다. 이게 핵심.
- 대부분의 이메일 툴에 기본 기능으로 있다. 별도 개발 불필요.

### 3. 랜딩 생성 자동화
- `landing/_template.html` + 변수 JSON → 생성 스크립트
- 목표: 새 유닛 랜딩 배포 **5분 이내**
- GitHub Pages 자동 배포 (main 브랜치 push = 배포)

### 4. 리퍼포징 배포 자동화
- 원본 1개(뉴스레터 또는 유튜브 대본) → 쓰레드/X/링크드인 초안 자동 생성
- 예약 발행까지 연결
- **이게 되기 전엔 SNS 채널을 늘리지 않는다.** (`01-OPERATING-SYSTEM.md` 램프업 7주차 조건)

### 5. 콘텐츠 제작 자동화
- 유튜브: 주제 → 대본 → TTS → 영상 조립
- 여기서 채널 폐쇄 가드레일이 가장 중요해진다 (`01-OPERATING-SYSTEM.md` §5)
- 자동 생성물을 **그대로 내보내지 않는다.** 주제·구성 판단은 내가 넣는다.

### 6. 수요 발굴 자동화
- 애널리틱스 + 댓글 스캔 → 주제 후보 랭킹
- 최종 선택은 항상 나. (`00-MASTER-PLAN.md` 궁극 목표 축에 부합하는지 판단이 필요)

## 스택 (현재 보유: 없음 → 0에서 세팅)

| 용도 | 선택 | 이유 | 세팅 시간 |
|---|---|---|---|
| 이메일 수집·발송 | **스티비** | 한국 서비스, 한글 UI, 국내 수신 안정성 | 1h |
| 결제·전달 | **Gumroad** | 디지털 상품 자동 전달, 세팅 최속 | 30m |
| 랜딩 | **GitHub Pages (이 레포)** | 무료, 코드 복제로 유닛당 비용 0 | 30m |
| 측정 | Google Sheets | 무료, Make 연동 | 30m |
| 자동화 | Make (무료 등급) | 노코드, 한국어 자료 많음 | 유닛 2부터 |

### ⚠️ 결제 수단에 대한 정직한 고지
- Gumroad는 세팅이 가장 빠르지만 **한국 고객 결제 UX(원화·간편결제)에서 불리할 수 있다.**
- 이건 확인되지 않은 우려이지 확정된 사실이 아니다.
- **대응:** 유닛 1은 Gumroad로 속도 우선. 게이트1은 통과했는데 게이트2가 계속 실패하면,
  **제품 문제가 아니라 결제 마찰일 수 있으므로** 국내 결제(스마트스토어·크몽·페이앱)로 1회 교체 테스트한다.
- 이 경우는 `03-KILL-SCALE.md`의 "제품 교체 재시도" 1회에 포함시키지 않는다. 결제 마찰은 별개 변수다.

### 사업자 등록 관련
유료 판매를 시작하면 한국에서는 사업자등록·통신판매업 신고가 필요할 수 있다.
⚠️ 세부 요건(간이과세 여부, 매출 기준, 신고 시점)은 확인하지 않았다.
**유닛 1에서 첫 매출이 발생한 시점에** 국세청/지자체 기준을 직접 확인하고 처리한다.
첫 제품 런칭 자체를 여기서 막지는 않되, 방치하지도 않는다.

## 자동화의 목표 수치

| 지표 | 지금 | 3개월 후 목표 |
|---|---|---|
| 유닛 1개 제작 시간 | ~20h | **4h 이하** |
| 유튜브 1편 제작 시간 | ? | 2h 이하 |
| 판정 1회 소요 시간 | — | 30분 (유닛 수와 무관하게 유지) |
| 동시 운영 유닛 수 | 1 | 4~6 |

**병렬 유닛 수의 상한은 "내 판단 시간"이어야 한다.**
제작 시간이 상한이 되어 있다면 자동화가 덜 된 것이다.
