# 01. 운영체제 — 하루와 한 주를 어떻게 쓰나

전제: **풀타임.** 다른 업무 없음. 대신 콘텐츠·제품·자동화를 고루 굴려야 함.

---

## 1. 하루 구조 (3블록)

풀타임이라도 한 종류만 하루 종일 하면 안 된다. 세 종류의 일은 뇌를 다르게 쓴다.
**블록 안에서는 종류를 섞지 않는다.**

| 블록 | 시간 | 하는 일 | 성격 |
|---|---|---|---|
| **A. 발행 블록** | 오전 4h (예: 09–13) | 콘텐츠 제작·발행 (유튜브/뉴스레터/쓰레드) | 창작. 방해 금지. |
| **B. 빌드 블록** | 오후 3h (예: 14–17) | 제품 개발 or 자동화 구축 (요일별 고정) | 엔지니어링 |
| **C. 계측 블록** | 저녁 1h (예: 20–21) | 숫자 기록, 로그 갱신, 다음날 준비 | 관리. 짧게. |

**A는 절대 침범당하지 않는다.** 트래픽이 끊기면 나머지 전부가 의미를 잃는다.
(콘텐츠 = 생명줄. 이건 우선순위가 아니라 전제다.)

### 계측 블록(C) 고정 절차 — 매일 10분이면 끝난다
1. `STATUS.md`의 숫자 3개 갱신: 노출/조회수, 이메일 수집 수, 매출
2. 오늘 발행한 콘텐츠에 **미끼 링크가 실제로 들어갔는지** 클릭해서 확인
3. 내일 A블록에서 만들 것 한 줄 적기
4. 끝. 이 블록에서 새 작업을 시작하지 않는다.

## 2. 주간 리듬

| 요일 | A블록 (오전) | B블록 (오후) |
|---|---|---|
| 월 | 유튜브 A(심리) 기획+대본 | 제품 빌드 |
| 화 | 유튜브 A 제작+업로드 | 제품 빌드 |
| 수 | 쓰레드 주간분 일괄 작성 | 자동화 빌드 |
| 목 | 뉴스레터 원고 *(4주차~)* | 제품 빌드 |
| 금 | 리퍼포징 (원본 → 타 채널) | 자동화 빌드 |
| 토 | **주간 리뷰 + 판정** (격주) | 다음 유닛 준비 |
| 일 | 오프 / 버퍼 | 오프 / 버퍼 |

**일요일은 비워둔다.** 밀린 걸 여기서 처리하려는 순간 시스템이 무너진다.
일요일에 일을 하고 있다면, 그건 주중 계획이 과했다는 신호다 → 토요일 리뷰에서 줄인다.

### 주기 요약
| 주기 | 무엇 |
|---|---|
| 매일 | 쓰레드 1개 발행 · 계측 10분 |
| 주 1회 | 유튜브 1편 · (4주차~) 뉴스레터 1편 |
| 2주 1회 | 유닛 1개 런칭 |
| 2주 1회 (토) | **판정일** — KILL / SCALE 결정 |
| 4주 1회 | 임계값·루틴 자체를 재조정 |

## 3. 램프업 일정 — 한 번에 다 켜지 않는다

각 단계는 **앞 단계가 "돌아간다"는 증거가 있을 때만** 켠다.

| 주차 | 새로 켜는 것 | 켜기 위한 조건(증거) |
|---|---|---|
| 1주차 | 유튜브 1채널 + 유닛 1 (미끼→랜딩→제품→메일) | 없음. 시작점. |
| 2주차 | 쓰레드 매일 발행 | 랜딩 E2E 테스트 통과 (내 이메일이 실제로 수집됨) |
| 3주차 | 유닛 2 착수 | 유닛 1이 **런칭 완료** (판정 결과와 무관) |
| 4주차 | 뉴스레터 시작 | **이메일 리스트 30명 이상** |
| 5주차 | 유튜브 2번째 채널(자기개발) | 유닛 1 판정 완료 + 유튜브 제작 과정이 문서화됨 |
| 7주차 | SNS 채널 확장 (X·링크드인) | 리퍼포징 자동화가 실제로 동작 |
| 9주차~ | 유닛 3~4 병렬 | 유닛 제작 시간이 **8시간 이하**로 떨어짐 |

> **조건을 못 채웠으면 그 주차엔 안 켠다.** 일정보다 조건이 우선이다.
> 조건 없이 켜면 늘어난 건 채널 수가 아니라 미완성 채널 수다.

## 4. 나만 하는 일 vs 에이전트가 하는 일

```
내 시간 = 판단
제작 · 배포 · 측정 = 에이전트
```

| 단계 | 담당 | 도구 |
|---|---|---|
| 수요 발굴 (유튜브 분석·댓글 스캔) | 에이전트 | Claude |
| 제작 (이북/PDF/워크북 초안) | 에이전트 | Claude |
| 카피·랜딩·판매메일 3통 | 에이전트 | Claude |
| 결제·배포 세팅 | 에이전트 + 나(1회 세팅) | Gumroad / Make |
| 측정·집계 | 에이전트 | Make + 스프레드시트 |
| **주제 선택** | **나** | — |
| **최종 검수** | **나** (유닛당 30분) | — |
| **킬/스케일 판정** | **나** (격주 30분) | — |

**내가 직접 하면 안 되는 일:** 초안 쓰기, 대량 읽기, 반복 작업, 포맷 변환.
이걸 직접 하고 있으면 병목은 내가 된다. 유닛 개수의 상한은 **내 판단 시간**이어야지 제작 시간이면 안 된다.

## 5. 채널 폐쇄 회피 가드레일 (필수)

수익 정지는 감수한다. **폐쇄는 감수하지 않는다.** 업로드 전 매번 확인:

- [ ] 타인 영상·이미지·음원을 **그대로** 쓰지 않았다 (재가공·자체 제작·라이선스 확인)
- [ ] 자동 생성 텍스트를 그대로 읽지 않고, **주제·구성에 내 편집 판단**이 들어갔다
- [ ] 의료·심리 주제에서 **진단·치료 효과를 단정하지 않았다** ("치료된다" X → "도움이 될 수 있다" O)
- [ ] 자해·자살 관련 표현은 유튜브 가이드라인에 맞춰 처리했고, 필요시 상담 안내를 넣었다
- [ ] 썸네일·제목이 내용과 일치한다 (오도성 메타데이터 = 폐쇄 사유)
- [ ] 같은 영상을 대량 반복 업로드하지 않았다
- [ ] 커뮤니티 가이드 위반 경고가 누적 중이면 **업로드를 멈추고 원인부터 제거**한다

> 심리 주제는 유튜브가 민감하게 보는 영역이다. 위 항목 중 3번(효과 단정)이 가장 실수하기 쉽다.
> ⚠️ 이 체크리스트는 일반적 정책 이해에 기반한 것이다. 유닛 1 런칭 전에 유튜브 커뮤니티 가이드
> 원문(특히 '스팸 및 기만행위', '민감한 콘텐츠')을 직접 확인해 항목을 보강할 것.

## 6. 시스템이 무너지고 있다는 신호

아래가 보이면 **속도를 늘리지 말고 줄인다.**

| 신호 | 의미 | 대응 |
|---|---|---|
| 일요일에 일하고 있다 | 주중 계획 과부하 | 다음 주 유닛 수 -1 |
| 판정일을 넘겼다 | 알고리즘 정지 | 즉시 판정. 예외 없음 |
| 발행 블록(A)을 이틀 이상 건너뜀 | 생명줄 손상 | 제품·자동화 전부 중단, A만 복구 |
| 미끼 링크 없는 콘텐츠를 발행했다 | 퍼널 누수 | 즉시 설명란 수정 |
| 유닛이 3주 넘게 "제작 중" | 완성도 함정 | 현 상태로 강제 런칭 |
| 죽여야 할 유닛을 못 죽이고 있다 | 판정 회피 | `03-KILL-SCALE.md` 재독 |
