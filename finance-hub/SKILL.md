[5] 크레딧·구독 팔로우업 (구독 대장 + 사용량 스냅샷) — 2026-11-13 대표님 지시
목적: 구독 대장의 크레딧 칸을 매일 채워 노션 공식이 '페이스(🔴 과속/🟢 여유)·HP 게이지·격차 막대'를 그리게 하고, 결제일·해지 상태를 따라갑니다. 기준 페이스 = 주기 크레딧 × 경과일 ÷ 주기 일수(비면 30). 실제 사용 = 주기 크레딧 − 남은 크레딧. 격차 = 실제 사용 − 기준 페이스(+면 과속, −면 여유).
대상 행: 구독 대장에서 서비스 제목이 'ElevenLabs', 'Higgsfield', 'Anthropic Claude'로 시작하는 행. 행이 없으면 새로 만들지 말고 보고합니다. 날짜는 모두 한국 시간 기준 날짜(is_datetime=0).

5-2 Higgsfield
- Higgsfield 연결의 balance 를 호출합니다(credits, subscription_plan_type). 생성·구매·요금제 도구는 절대 호출하지 않습니다. 연결이 없거나 실패하면 '실패(원인)'로 보고하고 넘어갑니다.
- 먼저 대장의 기존 '남은 크레딧'(어제 값)을 읽어 둡니다. 오늘 잔액이 어제 값보다 100 이상 늘었으면 '충전(지급) 감지'입니다:
  - transactions(size=100) 첫 페이지에서 action='grant' 항목을 찾으면 그 created_at의 KST 날짜를 주기 시작일로, 못 찾으면 오늘을 주기 시작일로 봅니다.
  - 대장: 주기 크레딧=오늘 잔액(이월분 포함), 크레딧 갱신일=주기 시작일+주기 일수(비면 30일).
  - 최종 보고에 '🔋 Higgsfield 충전 감지: 어제 A → 오늘 B (+C), 갱신일 추정 YYYY-MM-DD'를 씁니다. 갱신일은 추정이므로 대표님 확인 대상입니다.
- 크레딧 갱신일이 비어 있으면 주기 크레딧도 비워 둡니다(공식이 '⚪ 크레딧 정보 없음'으로 표시). 크레딧 갱신일이 오늘보다 과거인데 충전이 감지되지 않았으면 갱신일을 주기 일수만큼 미루지 말고 '갱신일 지났는데 충전 없음'으로 보고합니다.
- 대장: 남은 크레딧=credits, 크레딧 측정일=오늘. subscription_plan_type이 'ultra'가 아니면 '요금제 변경 감지'로 보고합니다.
- 사용량 스냅샷: 'Higgsfield YYYY-MM-DD'(오늘 KST) 행이 없으면 만듭니다. 서비스=Higgsfield, 단위=크레딧, 출처=API, 측정일시=오늘, 사용량=어제 잔액−오늘 잔액(충전 감지일이거나 어제 값이 없으면 비움), 비고='잔액 N · 요금제 X'(충전 감지일엔 '충전 감지' 추가).

5-3 Claude 사용량 분석 (이 PC의 로컬 로그 기준 — 다른 PC·클라우드·모바일 사용분은 빠짐을 보고서에 늘 표시)
Claude는 공식 크레딧 한도가 읽히지 않으므로 '직전 결제 주기에 실제로 쓴 양'을 기준선(=주기 크레딧)으로 삼아 같은 HP 게이지로 봅니다.
- 주기 계산: 대장 Claude 행의 다음 결제일 D. 이번 주기 = (D − 1개월) ~ (D − 1일). 직전 주기 = (D − 2개월) ~ (D − 1개월 − 1일).
- 이번 주기 누적 = 사용량 스냅샷의 'Claude Code YYYY-MM-DD' 일별 행(주간 행 제외) 중 이번 주기 시작일~어제의 사용량 합.
- 직전 주기 일별 행이 25일 이상 있으면: 대장 주기 크레딧=직전 주기 합, 남은 크레딧=max(0, 직전 주기 합 − 이번 주기 누적), 크레딧 갱신일=D, 주기 일수=이번 주기 날짜 수, 크레딧 측정일=오늘. 25일 미만이면 이 칸들을 비워 두고 보고서에 '기준선 쌓는 중 (직전 주기 N/30일)'.
- 매주 월요일에만 주간 행을 만듭니다: 'Claude 주간 YYYY-MM-DD'(지난주 월요일 날짜)가 없으면 서비스=Claude, 단위=토큰, 출처=로컬 로그, 측정일시=오늘, 사용량=지난주 월~일 합, 비고='일평균 N · 전주 대비 ±X% · 최대 사용일 MM/DD(N) · 메시지 N건 · 캐시읽기 N · 이번 주기 누적 N · 100만 토큰당 구독료 약 N원'. 마지막 값 = 대장 Claude 행 '월 원화 환산' ÷ (최근 30일 토큰 합 ÷ 1,000,000). 데이터가 모자라는 값은 '확인 못 함'.
- 매일 판정: 어제 토큰이 직전 7일 일평균의 2배 이상이면 '📈 Claude 사용 급증' 알림.

5-4 결제일·해지 추적
- [3]에서 오늘 새로 적재한 영수증 결제가 있으면, 같은 서비스의 대장 행에서 다음 결제일이 그 결제일 이전이거나 같을 때만 결제일+1개월(주기=연이면 +1년)로 바꿉니다.
- 상태가 '해지됨(이용중)' 또는 '종료'인 서비스에서 결제가 잡히면(영수증 또는 [4] 거래) '🚨 해지 후 결제' 알림. 상태·종료일은 바꾸지 않습니다(대표님 확인 대상).
- 상태 '활성'인데 다음 결제일이 오늘보다 과거면 날짜를 임의로 미루지 말고 '결제일 지남 — 영수증 확인 필요'로 보고합니다.

5-5 알림 판정 (공식 결과를 읽을 수 없으므로 대장 값으로 직접 계산)
- 🔴 페이스 과속: 격차 ÷ 주기 크레딧 > +10%p 인 서비스.
- 🪫 크레딧 부족: 남은 크레딧 < 주기 크레딧의 20%(=80% 소진).
- ⏰ 결제 임박: 상태 '활성'이고 다음 결제일까지 3일 이내 → '서비스 · 금액 통화 · D-n'.
